# ContributorOps Code of Conduct

ContributorOps is built around respectful open-source collaboration and maintainer trust. Everyone participating in this repository is expected to help keep the project useful, welcoming, and technically constructive.

## Expected behavior

- Be respectful in issues, discussions, reviews, and pull requests.
- Critique ideas and code, not people.
- Keep feedback specific, actionable, and relevant to the change being discussed.
- Respect maintainer decisions, project boundaries, and the safety model.
- Give credit for ideas, research, code, documentation, and design contributions.
- Prefer evidence, reproducible examples, and clear reasoning over adversarial debate.
- Assume good intent while still raising technical or safety concerns directly.

## Unacceptable behavior

- Harassment, threats, discrimination, or personal attacks.
- Spam, promotional flooding, or low-quality automated contribution activity.
- Deceptive claims about authorship, contribution impact, testing, or project status.
- Attempts to bypass ContributorOps approval gates or use the project for mass external writes.
- Publishing private information or credentials.
- Deliberately disruptive behavior that makes collaboration harder for other contributors.

## Project-specific trust rule

Any contribution that touches external GitHub writes must preserve the project rule that higher-risk actions remain explicitly human-approved. Changes that introduce mass commenting, mass PR creation, contribution gaming, or deceptive automation are outside project scope.

## Reporting a concern

For ordinary conduct concerns, open a private communication with the repository maintainer using the contact route listed on the ContributorOps website. For security vulnerabilities, follow [`SECURITY.md`](./SECURITY.md) instead of opening a public issue.

Maintainers may edit, hide, lock, or remove content and may restrict participation when behavior conflicts with these expectations.

## Scope

This code of conduct applies to ContributorOps repository spaces and to project-related interactions where someone is representing the project.
